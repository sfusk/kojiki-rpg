# 開発メモ

RPG古事記の作りと、これまでに決めたこと・つまずいたことの記録。
新しく手を入れるときは、まずここを読むと同じ穴に落ちずに済む。

- 公開URL: <https://sfusk.github.io/kojiki-rpg/>
- リポジトリ: `sfusk/kojiki-rpg`（public）
- 最終更新: 2026-09-05

---

## 1. 作業の進めかた

### 動かす

```
npm run dev      # http://localhost:8090/
npm test         # vitest run（290件）
```

ポート8090は Node 製の自作サーバー（`scripts/dev-server.mjs`）で、`Cache-Control: no-store`
を返す。8080は別プロジェクト（hino-ki-marketing.com）が使っているので避けること。

### バージョン識別子を必ず上げる

`js/data/version.js` の `VERSION`（例 `2026-09-05c`）をコード変更のたびに更新し、
タイトル画面右下の表示で目視確認する。

> **これは飾りではない。** NPCのすり抜けが直らないと二度報告を受けた原因は、
> コードではなく `python -m http.server` がキャッシュ制御を返さず、ブラウザが
> 古い `movement.js` を掴み続けていたことだった。修正が反映されないときは
> まずこの表示を見る。

### テスト中はBGMをOFF

ゆうすけさんからの指示。メニューの「音楽」で切れる。設定は localStorage に残る。

### コミットのメールアドレス

このリポジトリは公開済みで、履歴のメールは `sfusk@users.noreply.github.com` に
統一してある。個人メールで push しないこと（`git config user.email` を確認）。

## 2. 構成

```
index.html          canvas とタッチ操作ボタン、CSP
css/style.css       画面の縦並び、タッチボタンの見た目
js/main.js          ゲームループと各モードの update/draw
js/engine/          ロジック（データを持たない）
  input.js          キー入力・タッチ入力の状態
  movement.js       通行判定、NPCによる進入不可、海の航行
  renderer.js       マップ・スプライト・光の目印の描画
  window.js         ウィンドウ、メッセージ送り、選択肢、ページ分割
  events.js         イベントコマンドの実行
  flags.js          進行フラグ・持ち物・初期状態
  quiz.js battle.js save.js audio.js markers.js
js/data/            内容（ロジックを持たない）
  world.js          ワールドマップ（日本列島）と章の入口
  chapters/ch1..ch8 各章のマップ・NPC・トリガー・クイズ・語り
  readings.js       ふりがな辞書と本文への付与
  help.js           操作方法の案内文
  uiLayout.js       ウィンドウの寸法と地名の組み立て
  tiles.js sprites.js bosses.js codexData.js music.js version.js
tests/              vitest（実行時依存ゼロ、DOM非依存）
```

**エンジンとデータは分ける。** エンジンは章の中身を知らず、データはロジックを持たない。
`window.js` と `readings.js` のように、engine から data の定数を読むのは許容している。

## 3. 仕組みの要点

### イベントコマンド

`msg` / `set` / `give` / `take` / `orb` / `codex` / `if(then/else)` / `warp` / `quiz` /
`battle` / `story` の配列で書く。`story: 'prologue' | 'epilogue'` は章の導入・締めを
全画面で見せる。

### ワールドマップ（34×36）

`map.sailable === true` なので海（`~`）も進める（船で自動的に渡る扱い）。海上では
船のスプライトに切り替わる。章の中の川や池は `sailable` でないので従来どおり渡れない。

実際の日本列島の形に寄せてあり、北海道・本州・四国・九州・淡路島はそれぞれ独立した島。
**この独立性はテストで固定してある**（陸だけを辿った連結成分が混ざっていないこと）。

九州を西へ寄せる際、左端 x=1 が地図の縁で動かせなかったため、**西側に海を2列足して
幅32→34に広げ、九州以外を東へずらした**。座標を動かすときは `entry`・`triggers`・
各章の戻り先をまとめて直すこと。

| 章 | 題 | 現在の地名 | 入口 | タイル | 開放条件 | 戻り先 |
|---|---|---|---|---|---|---|
| ch1 | 第一章 オノゴロ島 | 淡路島 | (16,28) | 鳥居 | — | (16,29) |
| ch2 | 第二章 黄泉比良坂 | 東出雲 | (10,26) | 洞窟 | ch1_clear | (10,25) |
| ch3 | 第三章 高天原 | 天上の国 | (21,21) | 鳥居 | ch2_clear | (21,20) |
| ch4 | 第四章 出雲 | 奥出雲 | (9,26) | 鳥居 | ch3_clear | (9,25) |
| ch5 | 第五章 因幡・根の国 | 鳥取 | (12,25) | 鳥居 | ch4_clear | (12,24) |
| ch6 | 第六章 国譲り | 稲佐の浜 | (8,26) | 鳥居 | ch5_clear | (7,26) |
| ch7 | 第七章 日向 | 宮崎 | (6,31) | 鳥居 | ch6_clear | (5,31) |
| ch8 | 第八章 大和 | 奈良 | (17,25) | 鳥居 | ch7_clear | (17,24) |

旅の始まりは `(14,26)`（淡路島の対岸）。古事記の地上の物語はイザナギ・イザナミの
国生み＝オノゴロ島から始まるため、そこへ海を渡る位置に立たせている。
**`world.js` の `entry` と `flags.js` の `createState()` は同じ座標にすること**
（二重管理でずれ、海の上から始まる事故があった。今はテストで一致を保証している）。

### 道しるべの光（2種類）

| | 用途 | 付ける場所 | 消える条件 |
|---|---|---|---|
| `sparkle` | 章の中のまだ見ていない出来事 | 章のトリガー | そのフラグが立つ |
| `beacon` | 次に向かう章の入口 | ワールドの入口 | その章をクリアする |

どちらも `engine/markers.js` の `pendingMarkers()` が「条件（requires）を満たして
いるのに、まだフラグが立っていない」トリガーを選ぶ。結果として、ワールドでは常に
「次はここ」の一箇所だけが光る。章の出入口に `sparkle` は付けない（鳥居・洞窟の
タイルで位置が分かるため）。

### 地名の表示

章題に、そこに相当する現在の地名をかっこ書きで添える（`第一章 オノゴロ島（淡路島）`）。
`uiLayout.js` の `locationText()` / `menuLocationLines()` を描画とテストで共用する。
表示は3か所（フィールド左上のラベル・メニュー最初の画面・つよさ画面）。
高天原だけは天上界で現実の土地に対応しないため「天上の国」としている。

### 本文のふりがな

`readings.js` の `annotateReadings()` が固有名詞のうしろへ `（よみ）` を挿す。
すべてのメッセージ窓がこれを通る（`main.js` の `messageBox()`）。

- 同じ語は本文ひとつにつき最初の1回だけ
- 長い語を優先（「勾玉」より「八尺瓊勾玉」）
- **折り返しもここで行う。** 窓側の折り返しに任せると `（たかまがは／ら）` と
  読みが断ち切られるため、読みを崩さない位置で改行する
- 読みだけで1行（12文字）に収まらない語は作らない。「天叢雲剣」「鵜葺草葺不合命」は
  末尾の「剣」「命」を読みから外して見出しを短くしてある
- 「天下」のように動詞にもなる語は辞書に入れない（「天下った」に誤爆する）

### 操作

| | キーボード | タッチ |
|---|---|---|
| 歩く | 矢印キー | 十字ボタン |
| 決定・はなす | Z / Enter | けってい |
| メニュー | X / Esc | メニュー |
| 文章を送る | Z / Enter / 下矢印 | けってい |

タッチのボタンは押している間だけキーを押した扱いにする（`input.press/release`）ので、
ゲーム側は入力元を区別しない。表示するのは `pointer: coarse` **または**
`maxTouchPoints > 0` の端末（iPadはトラックパッドを繋ぐと coarse でなくなる）。

下矢印での送りには落とし穴がある。**歩きながら下矢印を押しっぱなしで話しかけると、
窓が開いた瞬間にその押下で1ページ飛ぶ**ので、窓を作るときに押下を捨てている
（`messageBox()` の先頭）。

操作方法はタイトル画面とメニューの「そうさ」から3ページで読める（`data/help.js`）。
メニューの分岐は項目の位置ではなくラベルで判断すること（項目を増やすとずれる）。

## 4. 公開

`main` へ push すると `.github/workflows/pages.yml` が走り、テストが通ったときだけ
GitHub Pages へ配信する。反映まで1〜2分。

セキュリティ面で入れてあるもの:

- **CSP**（`index.html`）: 外部リソースを一切読まないページなので `default-src 'none'`。
  CDN・フォント・API通信ゼロ、`eval` も `innerHTML` も使っていない
- **Actions の権限は最小**: `contents:read` / `pages:write` / `id-token:write` のみ。
  配信するのは `index.html`・`css`・`js` だけで、テストや依存は含めない
- **履歴の掃除**（2026-09-05実施）: 初期コミットに入っていた node_modules（16MBの
  バイナリ）を除去し18MB→308KB、コミッターのメールを noreply に置換。
  バックアップは `~/Projects/kojiki-rpg-backup-20260905.bundle`

## 5. 過去にはまったこと

| 症状 | 本当の原因 |
|---|---|
| NPCのすり抜けが直らない | ブラウザが古いJSをキャッシュしていた。dev サーバーを no-store にし、バージョン表示を追加して解決 |
| 第二章が進行不能 | NPC衝突を入れた副作用で、入口の隣に立つイザナギが一本道を塞いだ。到達可能性のBFSテストを追加 |
| 開始位置が海の上 | `entry` と `createState()` の二重管理。マップを作り替えたときに片方だけ直していた |
| 九州と本州が陸続き | 見た目では分からない1マスの繋がり。連結成分テストで固定 |
| クイズの選択肢がはみ出す | 13文字の選択肢。窓幅に収まるかをテストで検証するようにした |
| ふりがなが行またぎで割れる | 窓側の折り返しに任せていた。付与側で折り返すよう変更 |

**テストは「一度やらかしたこと」を書き留める場所として使っている。**
地形をいじる、NPCを動かす、文章を足す——どれも人の目では見落とすので、
落ちるテストが先に教えてくれる状態を保つこと。
